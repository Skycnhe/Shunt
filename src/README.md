# src/：server.py 的源码片段

设备上运行的是仓库根目录的单文件 `server.py`，它由这里的片段**按文件名顺序合并**生成：

```sh
python3 tools/build.py          # 改完 src/ 后重新生成 server.py
python3 tools/build.py --check  # 检查是否一致（CI 会跑）
python3 tools/build.py --split  # 直接改了 server.py 时，按片段标记拆回 src/
```

- 片段不是独立的 Python 模块，它们共用一个全局命名空间，跟拆分前的 server.py 完全一样，所以片段之间可以直接调用
- 编号表示顺序：00 基础常量 · 01–05 数据 / 链接解析 / 策略组 / mihomo 配置 / 核心接口 · 10–17 sing-box · 20–22 面板更新 / 内核更新 / 系统优化 · 30–36 认证、通知、延迟、统计、解锁、规则测试、日志 · 40–46 广告拦截、实时数据、定时任务、设备、诊断、DNS 防泄露 · 50–54 升级迁移、登录、HTTPS、访问控制、更新回滚 · 60–61 静态资源与 HTTP 接口 · 70 启动入口
- 新增片段时选一个合适的编号即可；放在被引用的定义之后（模块级代码按顺序执行，函数体里的引用没有顺序要求）
- 为什么不拆成真正的多文件部署：v7.2.0 之前的面板在线更新只会下载固定的几个文件。等设备都升到按 `update-files.txt` 清单更新的版本后，再考虑部署成 Python 包
